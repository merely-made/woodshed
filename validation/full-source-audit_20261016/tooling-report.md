### T2 — P2: Package source receipts are not bound to the executable they identify

**Trigger and evidence.** Build a release binary, change the checkout or lockfile, and package without rebuilding. Linux verifies only that the supplied revision equals the checkout's `HEAD` ([package-linux.sh:87–90](/Users/markik/Code/testing/woodshed/full-source-audit-20261016/source-d12201bf/scripts/package-linux.sh:87)), then accepts the already-existing executable ([package-linux.sh:112–119](/Users/markik/Code/testing/woodshed/full-source-audit-20261016/source-d12201bf/scripts/package-linux.sh:112)). It copies that executable and the current lockfile and hashes both ([package-linux.sh:137–143](/Users/markik/Code/testing/woodshed/full-source-audit-20261016/source-d12201bf/scripts/package-linux.sh:137)), then emits the current revision as `source_revision` ([package-linux.sh:182–191](/Users/markik/Code/testing/woodshed/full-source-audit-20261016/source-d12201bf/scripts/package-linux.sh:182)). None of these checks establishes that the executable was built from that revision or lockfile. The macOS packager similarly accepts an existing binary at [package-macos.sh:41–42](/Users/markik/Code/testing/woodshed/full-source-audit-20261016/source-d12201bf/scripts/package-macos.sh:41), obtains a source label from unchecked `GITHUB_SHA` or current `HEAD` at [package-macos.sh:56–60](/Users/markik/Code/testing/woodshed/full-source-audit-20261016/source-d12201bf/scripts/package-macos.sh:56), and prints it into the artifact at [package-macos.sh:123–140](/Users/markik/Code/testing/woodshed/full-source-audit-20261016/source-d12201bf/scripts/package-macos.sh:123). Windows packages an existing binary and current lockfile but emits no source revision at all ([package-windows.ps1:18–20](/Users/markik/Code/testing/woodshed/full-source-audit-20261016/source-d12201bf/scripts/package-windows.ps1:18), [package-windows.ps1:33–55](/Users/markik/Code/testing/woodshed/full-source-audit-20261016/source-d12201bf/scripts/package-windows.ps1:33)).

**Effect.** A checksummed archive can identify a new source/lock cohort while containing an older executable. The digest proves which bytes were archived; it does not validate the source claim. The existing build-first usage text is a manual precondition, not a checked provenance binding. No existing published artifact was examined or found stale here.

**Smallest coherent correction.** Produce a build receipt at the successful locked release build, binding source revision and tree state, Cargo.lock digest, actual target, and binary digest. Each packager should consume that receipt and refuse a mismatch before writing the archive. Obtain the source label from the verified receipt; validate any `GITHUB_SHA` override against it. Include the verified receipt in all three platform packages. This preserves separate platform packaging while giving build provenance one authority.

### T7 — P3: The macOS architecture-membership test only accepts the final architecture
