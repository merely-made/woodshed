Prepared October 17, 2026, from the eleven published-source partitions, the parent [audit synthesis](AUDIT.md), and the separately frozen [P5a overlay review](local-overlay-report.md).

Start with preservation, identity consent and malformed-model admission. Repair the evidence helpers alongside those changes so subsequent qualification can be trusted. Then correct material, playback and host projections through their existing owners. Retire unused implementations after checking compatibility. Keep P5a under its current implementation owner and its own acceptance receipt.

The published baseline is `d12201bfe80cc94345c6308c46caaebf4a9fe42e`. Its recorded collective scope is 936 assigned files and 231,127 lines, plus the parent's additional 63-line W3C definition: 937 files and 231,190 lines. The assigned hashes and read ranges were rechecked for this consolidation with no gaps or mismatches; all eleven published-partition reports and the parent synthesis still match `audit-receipt.json`. The separate overlay report completed its full semantic continuation on October 17 and was reread for this plan. These facts establish the audit inputs, not the current checkout's defect or fix status. Implementation continued after the freeze.

## Priority and execution rules

The order below follows potential work loss, wrong identity, unbounded execution, wrong musical/output behavior, interaction failures, and finally maintenance cost. Source P1/P2/P3 severities remain in the linked reports; the package order does not recast every grouped item as equally severe.

Each package names a component owner rather than assigning a person. Effort is relative: **S** is a focused change within an established seam; **M** crosses several components of one product or needs integration fixtures; **L** includes supplier coordination, storage migration or several model boundaries. These are scope estimates, not calendar promises. Packages may contain several small commits; they are not invitations to make one broad refactor.

Before implementing a package, its owner records current HEAD and worktree state, refreshes the relevant remote, and compares the cited paths with the frozen finding. Mark each item still present, already fixed but awaiting qualification, already qualified with a named receipt, or superseded by an explicit ruling. Preserve active work. This plan authorizes planning only; product edits, deletion, publication and scheduling are separate actions.

The complete evidence remains in the original reports. IDs below are namespaced because `host:H1`, `hocket:H1` and `ringdown:R1` are different findings. A package is complete only after its actual producer-to-consumer path passes its stated acceptance, not when a helper self-test or an optimistic status field passes.
